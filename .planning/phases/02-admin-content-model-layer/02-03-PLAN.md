<threat_model>

## Scope

This plan adds database models and Django Admin configuration for visitor contact inquiries and career applications.

## Trust Boundaries

- In Phase 2, inquiry records are created and reviewed only through Django Admin or tests.
- In Phase 3, public write-only endpoints will create these records, so Phase 2 must avoid public list/detail exposure and prepare sensible validation fields.
- Stored submissions may contain personal data.

## STRIDE Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01 | Information Disclosure | Contact and career submissions | High | Mitigate | Do not add public read endpoints; keep data visible only in Django Admin for authenticated staff. |
| T-02 | Tampering | Stored inquiry records | Medium | Mitigate | Use Django Admin permissions and review-friendly fields/status filters. |
| T-03 | Repudiation | Submission review | Low | Mitigate | Store `created_at` and optional review status so admins can trace submission timing/state. |
| T-04 | Denial of Service | Future public form writes | Medium | Defer with guardrails | Do not add endpoints now; Phase 3 must validate and rate-limit/anti-spam if needed. |

</threat_model>
