<threat_model>

## Scope

This plan adds admin-managed repeatable content and catalog records that will later be exposed through public read APIs.

## Trust Boundaries

- Authenticated staff users manage records in Django Admin.
- Uploaded files/images are referenced by model fields but no public upload API exists in this phase.
- Catalog and repeatable content are not publicly exposed until Phase 3 serializers/views are added.

## STRIDE Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01 | Tampering | Repeatable and catalog records | Medium | Mitigate | Restrict modification to Django Admin staff and add visible admin list/search/filter controls. |
| T-02 | Information Disclosure | Testimonial/certification/award documents | Medium | Mitigate | Store file references only; defer public serving and serializer exposure to Phase 3 review. |
| T-03 | Denial of Service | Large unordered content collections | Low | Mitigate | Add deterministic ordering fields and indexes for future query patterns. |
| T-04 | Spoofing | Product/category slugs | Low | Mitigate | Use unique slugs and tests to avoid ambiguous frontend identifiers. |

</threat_model>
