# Plan 05-01: Dashboard foundation, models, auth shell

## Objective

Bootstrap the `dashboard` app, model migrations, Tailwind/HTMX base layout, staff auth, and `/api/admin/` foundation.

## Tasks

### T1 — Dependencies and settings
- Add `django-htmx`, Tailwind build approach (django-tailwind or documented static pipeline)
- `INSTALLED_APPS`: `dashboard`, `django_htmx`
- Env: `PUBLIC_WEBSITE_BASE_URL`, `ADMIN_NOTIFICATION_EMAILS`, `DASHBOARD_MAX_UPLOAD_MB`
- Middleware: `HtmxMiddleware`
- DRF: admin-only renderer classes; document browsable API off in production

### T2 — Model migrations
- `CompanyProfile`: `map_url`, `gstin`
- `SiteMediaBanner`: `cta_text`, `cta_button_url`
- `ContactInquiry`, `JobApplication`: `internal_notes`
- `AdminAuditEntry` model + migration
- Update Django Admin fieldsets for new fields (fallback parity)

### T3 — Dashboard app shell
- `dashboard/urls.py` mounted at `/dashboard/`
- Base template: sidebar nav, header, messages, CSRF meta for HTMX
- `StaffRequiredMixin` + login/logout views
- Empty home view placeholder

### T4 — `/api/admin/` foundation
- Namespace `/api/admin/`
- `SessionAuthentication`, `IsAdminUser`
- Health/ping endpoint for AJAX auth check
- Shared staff serializer base (includes `id`, `is_active`, `order`, timestamps where applicable)

### T5 — Tests
- Login required redirects
- Staff vs non-staff access
- Migration smoke
