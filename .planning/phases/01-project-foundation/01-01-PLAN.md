<threat_model>

## Scope

Phase 1 creates settings, public API routing, CORS configuration, schema/docs exposure, static/media paths, and local database configuration.

## Trust Boundaries

- Environment variables cross from deployment/runtime into Django settings.
- Public HTTP clients can call `/api/health/`, `/api/schema/`, and `/api/docs/`.
- Admin routes exist but remain protected by Django's built-in admin authentication.
- Uploaded media paths are configured but public upload features are not implemented in this phase.

## STRIDE Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01 | Information Disclosure | Settings and `.env` handling | High | Mitigate | Keep `.env` ignored, provide `.env.example`, read secrets from environment, and never commit real secrets. |
| T-02 | Information Disclosure | API schema/docs | Low | Accept with guardrails | Expose only scaffold endpoints in Phase 1; review schema exposure before sensitive endpoints are added. |
| T-03 | Spoofing | CORS configuration | Medium | Mitigate | Configure `CORS_ALLOWED_ORIGINS` from env and avoid wildcard origins in production examples. |
| T-04 | Tampering | Static/media filesystem paths | Medium | Mitigate | Keep `MEDIA_ROOT` explicit, avoid write endpoints in Phase 1, and document Nginx/media handling for later deployment work. |
| T-05 | Elevation of Privilege | Admin route | Medium | Mitigate | Use Django admin auth only; do not add public user auth or custom admin bypasses in Phase 1. |

</threat_model>
